# Введение

## Цель работы  

Настроить взаимодействие через сеть провайдера посредством статической маршрутизации локальной сети организации с сетью основного здания, расположенного в 42-м квартале в Москве, и сетью филиала, расположенного в г. Сочи.

# Ход выполнения

В Packet Tracer был создан проект с распределённой топологией, включающей центральную сеть организации в Москве, сеть основного здания в 42-м квартале, сеть общежития, сеть филиала в г. Сочи и инфраструктуру провайдера. Для соединения сегментов использовались маршрутизаторы Cisco 2811, коммутаторы Catalyst 2950/2960 и промежуточные устройства провайдера.

![Общая топология сети организации и сети провайдера](Screenshot_1.png){ #fig:001 width=95% }

На стороне провайдера был настроен центральный коммутатор **provider-ngaforov-sw-1**. Для связи с удалёнными площадками интерфейсы были переведены в режим trunk. Также были созданы VLAN для отдельных направлений:

- VLAN 5 — сеть 42-го квартала;
- VLAN 6 — сеть филиала в Сочи.

Для созданных VLAN были назначены имена, после чего соответствующие VLAN-интерфейсы были активированы.

![Настройка VLAN и trunk на коммутаторе провайдера](Screenshot_2.png){ #fig:002 width=80% }

Далее была выполнена настройка маршрутизатора сети основного здания **msk-donskaya-ngaforov-gw-1**. На физическом интерфейсе FastEthernet0/1 были созданы подинтерфейсы с инкапсуляцией IEEE 802.1Q:

- FastEthernet0/1.5 — VLAN 5, канал к сети 42-го квартала;
- FastEthernet0/1.6 — VLAN 6, канал к филиалу в Сочи.

Каждому подинтерфейсу был назначен IP-адрес из /30-подсети. Такая маска используется для соединений «точка-точка», поскольку в сети остаются два доступных адреса для интерфейсов маршрутизаторов.

![Настройка подинтерфейсов на маршрутизаторе основного здания](Screenshot_3.png){ #fig:003 width=80% }

После этого был настроен маршрутизатор сети 42-го квартала **msk-q42-ngaforov-gw-1**. Физический интерфейс FastEthernet0/1 был включён, а на его базе создан подинтерфейс FastEthernet0/1.5. Для него была задана инкапсуляция dot1Q с номером VLAN 5 и назначен IP-адрес из сети соединения с основным зданием.

Также был создан VLAN 6 с именем **sochi**, предназначенный для передачи трафика филиала через сеть провайдера.

## Контрольные вопросы

### 1. Приведите пример настройки статической маршрутизации между двумя подсетями организации.

Статическая маршрутизация используется в том случае, когда администратор вручную задаёт путь до удалённой сети. Для этого на маршрутизаторе указывается сеть назначения, маска этой сети и адрес следующего маршрутизатора, через который нужно передавать пакеты.

Например, если в организации есть две удалённые подсети:

- сеть 42-го квартала — **10.129.0.0/16**;
- сеть филиала в Сочи — **10.130.0.0/16**;
- между ними находится сеть провайдера с адресами маршрутизаторов **10.128.255.1**, **10.128.255.2**, **10.128.255.5**, **10.128.255.6**,

то на центральном маршрутизаторе можно указать маршрут к сети 42-го квартала через соседний маршрутизатор **10.128.255.2**, а маршрут к сети Сочи — через **10.128.255.6**.

В общем виде статический маршрут задаётся так:  
**ip route [сеть назначения] [маска] [адрес следующего маршрутизатора]**

Например, для маршрута к сети Сочи может быть задано направление:  
**ip route 10.130.0.0 255.255.0.0 10.128.255.6**

Это означает, что все пакеты, предназначенные для сети **10.130.0.0/16**, маршрутизатор должен отправлять на следующий узел **10.128.255.6**.

Для обратной связи на маршрутизаторе филиала также должен быть задан маршрут обратно к сетям центральной организации. Если точные маршруты ко всем сетям не прописываются отдельно, можно использовать маршрут по умолчанию. Например, филиал в Сочи может отправлять весь неизвестный трафик через центральный маршрутизатор провайдера.

### 2. Опишите процесс обращения устройства из одного VLAN к устройству из другого VLAN.

Устройства, находящиеся в разных VLAN, относятся к разным логическим сетям. Даже если они подключены к одному коммутатору, напрямую обмениваться данными они не могут, потому что коммутатор второго уровня разделяет VLAN между собой. Для передачи данных между VLAN требуется маршрутизатор или L3-коммутатор.

Процесс обращения устройства из одного VLAN к устройству из другого VLAN происходит следующим образом:

1. Компьютер-отправитель определяет, что IP-адрес получателя находится в другой подсети.
2. Так как получатель находится не в локальной сети, компьютер отправляет пакет на свой шлюз по умолчанию.
3. Шлюзом обычно является IP-адрес подинтерфейса маршрутизатора, настроенного для данного VLAN.
4. Перед отправкой кадра компьютер выполняет ARP-запрос, чтобы узнать MAC-адрес шлюза.
5. После получения MAC-адреса шлюза компьютер формирует Ethernet-кадр и отправляет его на коммутатор.
6. Коммутатор передаёт кадр по trunk-порту к маршрутизатору, сохраняя VLAN-метку 802.1Q.
7. Маршрутизатор принимает кадр на соответствующем подинтерфейсе, удаляет VLAN-метку и анализирует IP-адрес назначения.
8. По таблице маршрутизации маршрутизатор определяет, через какой интерфейс нужно отправить пакет дальше.
9. Если сеть назначения находится в другом VLAN этого же маршрутизатора, пакет передаётся через другой подинтерфейс.
10. При передаче обратно в сеть получателя маршрутизатор формирует новый Ethernet-кадр с нужной VLAN-меткой.
11. Коммутатор получает кадр и отправляет его на access-порт, к которому подключено устройство-получатель.

Например, если компьютер из VLAN 201 обращается к компьютеру из VLAN 301, то трафик сначала поступает на шлюз VLAN 201, затем маршрутизируется в сторону VLAN 301 и только после этого доставляется конечному устройству.

Главное отличие такого обмена от передачи внутри одной VLAN заключается в том, что при межвлановом взаимодействии обязательно используется маршрутизация на третьем уровне модели OSI.

### 3. Как проверить работоспособность маршрута?

Работоспособность маршрута можно проверить несколькими способами.

Самый простой способ — использовать команду **ping**. Она отправляет ICMP Echo Request на удалённый узел и ожидает ICMP Echo Reply. Если ответы приходят, значит устройство доступно, а маршрут до него работает.

Например, если с компьютера сети 42-го квартала выполняется проверка доступности компьютера филиала в Сочи, то успешный ответ от адреса **10.130.0.200** подтверждает, что между сетями есть связность.

Более подробная проверка выполняется с помощью команды **tracert** на ПК или **traceroute** на маршрутизаторе. Эта команда показывает, через какие промежуточные маршрутизаторы проходит пакет до конечного узла.

По результатам трассировки можно определить:

- проходит ли пакет через правильный шлюз;
- на каком маршрутизаторе останавливается передача;
- есть ли обратный маршрут;
- достигает ли пакет конечной сети;
- сколько промежуточных переходов используется между сетями.

Также работоспособность маршрута можно проверить просмотром таблицы маршрутизации. Если в таблице есть нужная сеть назначения или маршрут по умолчанию, маршрутизатор сможет определить, куда отправлять пакеты.

Для диагностики обычно проверяют:

- IP-адреса и маски на интерфейсах;
- состояние интерфейсов;
- наличие маршрута до удалённой сети;
- наличие обратного маршрута;
- правильность указанного next-hop;
- доступность соседнего маршрутизатора;
- корректность VLAN и trunk-соединений.

### 4. Как посмотреть таблицу маршрутизации?

Таблица маршрутизации на маршрутизаторе Cisco просматривается командой **show ip route**.

В таблице маршрутизации отображаются все известные маршрутизатору сети и способы доступа к ним. Рядом с маршрутами указываются специальные обозначения:

- **C** — directly connected, сеть подключена напрямую к интерфейсу маршрутизатора;
- **L** — local, локальный IP-адрес самого интерфейса маршрутизатора;
- **S** — static, статический маршрут, добавленный вручную;
- **S\*** — статический маршрут по умолчанию;
- **R** — маршрут, полученный по протоколу RIP;
- **O** — маршрут, полученный по протоколу OSPF;
- **D** — маршрут, полученный по протоколу EIGRP.

Если в таблице есть строка вида **Gateway of last resort**, это означает, что на маршрутизаторе настроен маршрут по умолчанию. Такой маршрут используется тогда, когда для сети назначения нет более точной записи в таблице маршрутизации.

Например, если в таблице отображается запись **S\* 0.0.0.0/0 via 10.128.255.1**, это означает, что весь трафик к неизвестным сетям будет передаваться через маршрутизатор с адресом **10.128.255.1**.

Просмотр таблицы маршрутизации позволяет проверить, знает ли маршрутизатор путь до нужной сети и через какой next-hop он будет отправлять пакеты.
